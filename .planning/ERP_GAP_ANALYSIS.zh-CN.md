# AeroERP 对标主流 ERP 能力缺口与分阶段建设路线图

**更新日期：** 2026-07-08

## 1. 当前系统定位

AeroERP 当前已经完成的平台和业务能力，更准确地说是：

- 一个具备账号、角色、模块显隐、智能体审查能力的治理底座
- 一个具备主数据、采购申请、采购订单、采购入库、库存余额的最小业务闭环
- 一个按模块化单体 + 前后端分离 + UI 类库分层建设的新 ERP 骨架

因此，当前系统还不是完整 ERP，而是一个**采购到入库闭环已经跑通的轻量 ERP MVP**。

## 2. 当前已具备的能力

### 平台治理

- 登录、当前用户、角色权限
- 组织、角色、用户管理
- 模块显隐与模块权限
- 智能体动作提审、审批、审计

### 主数据

- 供应商
- 物料
- 仓库

### 采购与库存

- 采购申请
- 采购审核
- 采购转单
- 采购订单下达
- 采购入库
- 库存余额查询

## 3. 对标主流 ERP 的主要缺口

主流 ERP 一般至少覆盖财务、销售、采购、库存、计划、质量、报表和治理能力。对照你当前项目，缺口可以分成三层。

### 3.1 业务域缺口

#### 销售域缺失

- 客户主数据
- 销售报价
- 销售订单
- 发货/出库
- 销售退货
- 销售回款
- 销售分析

#### 财务域缺失

- 应收
- 应付
- 费用报销/付款申请
- 发票与税率
- 总账与凭证
- 成本核算
- 财务报表

#### 制造与计划域缺失

- BOM
- 工艺路线
- 工单
- 生产领退料
- 完工入库
- MRP / MPS
- 委外加工

#### 质量域缺失

- 来料检验
- 过程检验
- 出货检验
- 不合格品处理
- 质量追溯

### 3.2 流程闭环缺口

你现在已经有“采购到入库”的闭环，但还缺这些关键闭环：

- 销售到出库到回款闭环
- 采购到应付到付款闭环
- 库存出库、调拨、盘点闭环
- 主数据停用、归档、引用校验闭环
- 审批、待办、通知闭环
- 单据到财务凭证闭环

### 3.3 系统治理缺口

- 审批流引擎
- 待办中心
- 消息通知中心
- 数据权限
- 字段权限
- 审计日志深化
- 变更历史与版本留痕
- 单据编码规则
- 导入导出模板
- 多组织 / 多公司 / 多账套
- 多币种 / 税率 / 本地化财务规则
- 第三方接口集成
- PDA / 条码 / 扫码作业
- BI 报表和管理驾驶舱

## 4. 最需要优先补的部分

如果目标是尽快接近“可用 ERP”，建议按以下优先级推进。

### 第一优先级：先把交易主链补齐

1. 销售管理
2. 库存出库、调拨、盘点
3. 应收应付与基础结算
4. 审批流、待办、通知
5. 主数据生命周期管理

这一层补完后，系统才会从“采购入库型系统”升级为“进销存 + 基础结算平台”。

### 第二优先级：把治理和分析补深

1. 报表中心 / BI
2. 数据权限
3. 编码规则
4. 多组织、多仓、多币种
5. 供应商/客户协同

### 第三优先级：再向制造型 ERP 扩展

1. BOM / 工单 / 完工入库
2. MRP / 计划
3. 质量管理
4. 委外
5. PDA / 条码 / 追溯

## 5. 从你当前架构出发的模块化建议

建议继续保持“一个业务域一个模块包”的做法，并把共享契约、UI 风格、页面壳、流程引擎继续隔离。

### 建议新增后端模块

- `AeroERP.Modules.Sales`
- `AeroERP.Modules.Finance`
- `AeroERP.Modules.Warehouse`
- `AeroERP.Modules.Workflow`
- `AeroERP.Modules.Reporting`
- `AeroERP.Modules.Planning`
- `AeroERP.Modules.Quality`

### 建议保持的边界

- `Platform`：身份、权限、模块可见性、智能体审查、审计
- `MasterData`：客户、供应商、物料、仓库、计量单位、分类
- `Sales`：报价、订单、发货、退货、回款关联
- `Procurement`：申请、审批、订单、供应商协同
- `Warehouse`：入库、出库、调拨、盘点、库位、批次
- `Finance`：应收、应付、收付款、票据、凭证事件
- `Workflow`：审批流、待办、通知、业务动作编排
- `Reporting`：统计口径、报表接口、驾驶舱

### 前端建议

- `packages/ui-style`：设计变量、动效、主题
- `packages/ui-kit`：通用交互组件
- `apps/web`：业务页面组合与路由
- 页面层只组织交互，不承载业务规则
- 业务规则、状态流转、校验逻辑优先落在模块服务与契约层

## 6. 推荐分阶段路线图

下面的阶段顺序，是按“先补闭环，再补治理，再补制造”的原则给出的。

### 里程碑 2：从采购库存扩展到进销存

#### Phase 7：销售基础闭环

- 客户主数据
- 销售报价
- 销售订单
- 销售订单状态流转
- 销售模块前端页面与权限显隐

**完成标准：**
用户可以从客户与物料出发创建销售订单，并看到订单状态变化。

#### Phase 8：库存执行深化闭环

- 销售出库
- 库存调拨
- 库存盘点
- 出入库流水
- 库位基础能力

**完成标准：**
库存不再只有“采购入库”，而是具备完整的进出调盘能力。

#### Phase 9：应收应付与基础结算

- 采购应付
- 销售应收
- 收付款登记
- 业务单据和结算单关联

**完成标准：**
采购和销售单据都能进入基础结算链路。

### 里程碑 3：治理深化与管理驾驶舱

#### Phase 10：流程引擎、待办、通知

- 通用审批定义
- 单据审批路由
- 待办中心
- 站内通知
- 审批历史

**完成标准：**
关键业务动作不再靠页面内按钮直接推进，而是进入可追踪的流程审批体系。

#### Phase 11：报表、数据权限、编码规则

- 采购、销售、库存统计
- 角色 + 数据范围权限
- 单据编码规则
- 导入导出能力

**完成标准：**
平台具备企业运营分析和更细粒度的管控能力。

#### Phase 12：多组织与基础本地化

- 多组织 / 多公司
- 多仓权限隔离
- 多币种
- 税率与基础票据字段

**完成标准：**
系统能支撑更接近真实企业的组织与结算环境。

### 里程碑 4：制造与质量扩展

#### Phase 13：制造基础

- BOM
- 工单
- 生产领料
- 完工入库

#### Phase 14：质量与追溯

- 来料检验
- 过程检验
- 出货检验
- 批次追溯

#### Phase 15：计划与协同

- MRP / 补货建议
- 委外加工
- 供应商协同
- 条码 / PDA

## 7. 最小任务拆分原则

后续每个阶段建议继续按你已经要求的方式推进：

1. 先定义业务闭环，再拆 API、领域对象、页面和权限
2. 每个模块都必须有真实 UI，不允许只有接口没有页面
3. 每个页面都必须有空状态、加载态、错误态、成功态
4. 每个业务动作都必须有可见反馈，不允许死按钮
5. 每个模块都必须纳入插件目录、模块权限、导航显隐和审计
6. 每个新智能体动作都必须进入审查链路

## 8. 一句话结论

你现在最缺的，不是更多页面，而是：

**销售、结算、库存深化、流程治理、数据治理这五条主链。**

这五条补起来之后，AeroERP 才会从“采购库存 MVP”进入“可持续扩展的企业 ERP 基础平台”。
